# The mobile app is a native Android app in `android/`

The whole prototype (Worker and Foreman roles, every screen) is ported to a native Android app written in Kotlin with Jetpack Compose and Material 3, in a new root folder `android/` beside `frontend/` and `backend/`. The prototype already has an Android Material 3 look, and a native client gives the best camera QR scanning, audio recording, notification channels and Android App Links for factory-floor phones. The contract between app and backend is a markdown document ([MOBILE_API_CONTRACT.md](../MOBILE_API_CONTRACT.md) for endpoints, [MOBILE_PLATFORM_CONTRACT.md](../MOBILE_PLATFORM_CONTRACT.md) for push, deep links, version gate, offline queue and uploads) plus XREQ cards, not a hand-written OpenAPI file, because `docs/openapi.yaml` is generated from the FastAPI routes ([ADR 0006](0006-code-first-openapi.md)) and the planned endpoints do not exist in code yet. Rejected: React Native with Expo (would share TypeScript domain code and the generated API types with the web app, but the team chose the native look and platform features), a Capacitor wrapper of the web app (fast, but it looks like the website), and Flutter (a new language and no code sharing with the web). Distribution (decided 2026-11-23): no Google Play upload for now. The applicationId is `com.techtsunagu.wakatta` and the signed release APK is distributed directly, kept in the repo under `android/release/`; the signing keystore is never committed: one named owner creates it, keeps two offline backups and builds every release APK. Only the latest `wakatta-<version>.apk` and its SHA-256 file stay in `android/release/` (plain git, no LFS). The backend was hosted on 2026-11-23 (Azure Container Apps, XREQ-008 resolved), so the app talks to it: the server address and every endpoint path live in one file, `ApiConfig.kt` in `:core:network`, and changing the server is a one-line edit there. Areas whose backend routes do not exist yet (Contacts, My QR, Talk Threads, group controls, notification list) keep a Fake repository until they do. Contact messages send a generic push with no text; Talk Threads never notify. Consequences: the Android client's API types are written or generated separately from the web client's, so the contract document and `docs/openapi.yaml` must stay in step; releases go through Google Play (or a direct APK for a pilot) with their own signing and CI; push uses Firebase Cloud Messaging only; iOS is not covered, and adding it later means a second client against the same contract.
