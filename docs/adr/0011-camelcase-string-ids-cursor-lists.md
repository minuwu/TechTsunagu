# camelCase JSON, string ids and cursor-paged lists

The API sends camelCase keys (Pydantic `alias_generator=to_camel`), serialises every id as a string, and pages every list with `?limit=&cursor=` returning `{items, nextCursor}`. The frontend was built first, on mock data, with camelCase types and string ids in `frontend/src/domain/wakatta.ts`; matching it is one setting in the backend, while snake_case would mean rewriting every frontend type and screen. Ids stay `bigint` identity in Postgres (small, sequential indexes); exposing them is harmless because every lookup is scoped to the caller's shop or district ([ADR 0009](0009-shop-and-district-scopes.md)). Cursors replace the template's `page`/`page_size`/`total` because feeds such as Confusions, Checks and Asks only grow, and an offset with a total count gets slower with every row while a keyset cursor does not.
