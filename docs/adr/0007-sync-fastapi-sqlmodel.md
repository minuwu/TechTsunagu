# Synchronous endpoints, sync SQLModel, inline AI calls

Route handlers are plain `def` functions using a synchronous SQLModel session on psycopg 3; FastAPI runs them in its thread pool, so a slow database or AI call never blocks the event loop. AI calls run inline inside the request with a 45-second timeout and a 60-second budget, and no database transaction is held open across a model call. Async SQLAlchemy was rejected because mixing `async` routes with sync libraries is the easiest way for five people working in parallel to block the event loop by accident, and the load (one shop, a few devices polling every 2–5 seconds) is far below what the thread pool handles. A job queue for AI work was rejected because Azure Container Apps' 240-second ingress timeout covers the longest call, and a queue would add a worker process, retries and a status endpoint for no gain in the demo. Revisit if AI calls regularly exceed 30 seconds or the API needs more than one replica.
